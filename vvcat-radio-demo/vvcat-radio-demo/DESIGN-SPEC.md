# VVcat Radio 网站重设计方案 v2

> 项目地址：<https://vvcat-radio.pages.dev/>  
> 设计目标：保留现有复古收音机与猫队长的个性，在不丢失已有内容和功能的前提下，重新建立清晰的页面叙事、导航和播放体验。  
> 页面顺序必须为：**头部导航 → 个人介绍 + 像素猫小游戏 → 收音机 → 作品展示 → 页脚**。全站底部另有一个始终可见的常驻播放栏。

---

## 1. 设计原则

1. **先介绍，再试听，最后看作品。** 访客进入页面后，应立即理解“猫队长是谁、擅长什么、可以为哪些项目制作音乐”，然后试听音乐，最后查看合作项目和原创作品。
2. **在现有网站基础上改版，不推倒重做。** 保留现有复古收音机、音乐列表、播放控件、猫形象、访客计数器、作者署名和原有介绍文字。可以调整布局与入口，但不能无故删除功能。
3. **风格保持个人化。** 继续使用复古电器、像素游戏、黑橙色猫和轻松的文字语气，不改成普通商务公司官网或过度正式的音乐人模板。
4. **让下一步操作一眼可见。** 头部导航清晰；介绍区有“试听音乐”和“查看作品”两个明确入口；作品卡片有清楚的点击反馈。
5. **不虚构履历。** 只展示实际存在的音乐作品和合作项目，不增加未经确认的客户、商业项目数量、游戏销量、获奖经历或专业资历。

## 2. 页面信息架构与顺序

### 2.1 桌面端整体布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ [现有 Logo] 猫队的收音机 vvcatのradio   介绍  收音机  作品  关于  [合作联系] │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  介绍文本（左侧）                         像素猫跑酷小游戏（右侧） │
│  猫队长是谁、音乐风格、合作方向           CAT RUNNER              │
│  [去收音机试听] [看作品]                  猫跳跃、躲障碍、计分      │
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│  02 / RADIO                                                     │
│  现有复古收音机：屏幕、歌曲列表、上一首/播放暂停/下一首、音量等   │
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│  03 / SELECTED WORKS                                             │
│  合作项目：方形封面与作品名卡片，像唱片一样陈列                  │
│  [《缚语》] [《缚育宅姬》] [其他已确认项目……]                     │
│                                                                  │
│  原创音乐：保留现有音乐作品，可选择试听或在收音机中播放           │
├──────────────────────────────────────────────────────────────────┤
│  页脚：make by vvcat / 访客计数器 / 合作联系入口                  │
└──────────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────────┐
│ [封面] 曲名 / 作者     [上一首] [播放/暂停] [下一首]  ━━━━━━━  音量  列表 │ ← 常驻底部播放栏
└──────────────────────────────────────────────────────────────────┘
```

底部播放栏固定在浏览器可视窗口底部，不占用页面正文的正常排版空间；正文最下方必须预留足够的 `padding-bottom`，避免页脚或作品卡片被播放栏遮挡。

### 2.2 头部导航

头部导航应始终清晰可见，桌面端使用横向导航，建议采用吸顶方式。导航项目使用页面内锚点，不应点击后跳到不相关页面。

| 导航文字 | 目标区域 | 作用 |
|---|---|---|
| 介绍 | `#intro` | 回到个人介绍区 |
| 收音机 | `#radio` | 跳到复古收音机和歌曲列表 |
| 作品展示 | `#works` | 跳到合作项目与原创音乐 |
| 关于猫队长 | `#about` 或现有介绍弹窗 | 查看完整自我介绍；可复用现有“点击了解我”入口 |
| 合作联系 | 配置好的联系地址或联系区域 | 给游戏作者、OC 作者、短片/PV 制作者一个明确的联系入口 |

- 左上角保留现有 Logo 资源和“猫队的收音机 vvcatのradio”品牌文字。
- 导航中的当前区域可有简洁的高亮状态。
- “合作联系”应视觉上较为突出，但不能盖过网站的个人创作气质。
- 联系方式目前未在本需求中确认，开发时应使用项目配置中的真实联系方式；没有配置时，不要编造邮箱或社交账号。
- 手机端可以将导航压缩为菜单，但菜单展开后每个入口仍必须有清晰文字，不能只依赖图标。

## 3. 第一屏：个人介绍 + 像素猫小游戏

### 3.1 版式

介绍区是页面打开后首先看到的正文区域，桌面端采用左右双栏：

- **左侧约 50%–55%：** 介绍文案、擅长曲风、合作方向与行动按钮。
- **右侧约 45%–50%：** 像素猫跑酷小游戏。游戏作为有趣的个人标志，不应比介绍文案更抢眼，也不应影响访客快速读懂介绍。
- 两侧上下对齐，留白充足；区块底色和边框沿用网站复古收音机的暖色调。
- 建议使用浅暖色背景、深色文字和橙色强调色。保留像素/复古元素，但正文必须易读。

### 3.2 介绍文案

文案以现有介绍为基础，不添加未经确认的履历。可以按视觉需要换行、加粗关键词，但不要删掉原有信息。建议在左侧直接展示：

**主标题：**

> 俺是猫队长，喜欢捣鼓音乐。

**正文：**

> 俺是一只黑橙色的猫，喜欢捣鼓音乐。  
> 业余音乐作者，会做电子、氛围、弱管弦、钢琴，以及一些日式、中式和凯尔特风格的音乐。  
> 比起炫技，更喜欢给游戏、角色和故事做一点刚刚好的声音。

**适用项目：**

> 独立游戏 / OC / 短片 / PV / 剧情配乐均可。

**收尾文案：**

> ……如果你刚好也缺一只会写BGM的猫，可以叫俺。ฅ^•ﻌ•^ฅ

**按钮：**

- `去收音机试听`：滚动到 `#radio`。
- `查看作品`：滚动到 `#works`。

按钮需要有可见的 hover、键盘焦点和点击状态。手机端上下排列，介绍文案在上，小游戏在下。

### 3.3 像素猫跑酷小游戏

小游戏借鉴经典浏览器恐龙跑酷的简单玩法，但角色和美术需要为猫队长重新绘制，不能直接把通用猫素材替换上去后就视为完成。

**视觉要求**

- 主角必须基于网站现有的黑橙色猫形象制作像素版本，保留可以辨识的配色、轮廓或标志性细节。
- 采用清晰的像素网格，放大时保持硬边，不要使用模糊缩放。
- 场景简洁，类似经典横向跑酷：地面、少量背景装饰、计分区域、障碍物和重新开始提示。
- 障碍物可以重新设计成与音乐主题相呼应的物件，例如磁带、音箱线圈或唱片堆；如要保留仙人掌式障碍，也应使用原创绘制，不直接照搬原游戏素材。
- 整体配色融入网站黑色、橙色、奶油白和复古灰，不做高饱和霓虹风。

**玩法要求**

- 初始状态：显示静止像素猫及简短提示，例如“按空格或点击开始”。不要打开网页后立刻自动开始，以免打断阅读。
- 开始后：猫自动向前跑，玩家通过跳跃躲避障碍；碰到障碍后显示分数及重新开始操作。
- 键盘：`Space` 或 `↑` 跳跃；游戏获得焦点时才拦截空格键，不能影响页面其他控件。
- 鼠标：点击游戏区域开始/跳跃；提供明确的重新开始区域。
- 手机：点击或轻触游戏区域跳跃；触控范围足够大，不依赖 hover。
- 记录本轮分数及本地最高分即可；如果不准备维护持久化机制，页面刷新后分数重置也可接受，但界面行为需要明确。
- 游戏结束状态需有“再玩一次”提示。跳跃、碰撞和计分反馈应清楚，但动画不要过度。
- 游戏不能抢走音频播放控制权，也不能因键盘输入导致网页误滚动。
- 尊重系统减少动态效果设置；在低性能设备上应保持可玩。

**角色素材需求**

至少准备以下状态：静止、跑步（2 帧或以上）、跳跃、碰撞/失败。优先以透明背景 PNG 精灵图或统一规格的 sprite sheet 交付。若目前的猫图只有单张静态插画，需要重新制作或像素化绘制，不要随意使用网上的橘猫动画替代。

## 4. 第二部分：复古收音机

收音机仍是网站的核心听觉体验。位置放在介绍区之后，作品展示之前；保留现有造型和交互，不把它替换成通用音乐播放器。

### 4.1 必须保留的内容

- 现有收音机外观与 `MR-01 / LITTLE RADIO / LISTENING...` 等视觉元素。
- 现有歌曲列表及其数据来源，包含目前已配置的音乐文件和曲目信息。
- 当前曲目/播放状态区域，包括 `NOW PLAYING`、加载状态、`READY` 等状态反馈。
- 上一首、播放/暂停、下一首三个控制。
- 当前播放进度、已播放时间、总时长及可拖动进度条。
- 音量控制及当前音量显示。
- 点击歌曲列表中的作品可以开始播放。
- 空列表、加载中、播放失败等状态需要有可理解的提示，不能一直停留在“正在读取音乐作品…”。
- 现有“点击了解我”入口及其介绍功能应保留，可继续打开关于猫队长的介绍弹窗；弹窗可复用第 3.2 节的原文。
- 原有卡通小猫图片继续使用在合适的位置，不应因为新增像素游戏而删除原插画。

### 4.2 与底部播放栏共用同一套播放状态

收音机控件和底部播放栏是同一播放器的两组控制界面，不能分别创建两套独立音频实例。

- 在收音机选择一首歌，底部栏立即显示同一曲目。
- 在底部栏切换歌曲，收音机的歌曲列表选中状态同步更新。
- 在底部栏播放/暂停，收音机的状态文字和控件状态同步更新；反向操作亦然。
- 两处显示的播放进度、时长、音量和曲目必须一致。
- 页面滚动、点击导航、打开介绍弹窗或开始小游戏时，不应意外重新加载歌曲或把播放进度归零。

## 5. 第三部分：作品展示

作品区位于收音机之后。它既承担展示合作项目的作用，也保留用户原有的个人音乐作品内容。

### 5.1 区块层级

建议标题为：

**03 / SELECTED WORKS**  
**一些声音，后来有了自己的世界。**

作品区分为两个子区块，避免把合作项目与个人试听曲目混为一谈：

1. **合作项目**：优先展示已确认的游戏/项目封面。
2. **原创音乐**：保留现有个人音乐作品，可试听或在收音机中播放。

### 5.2 合作项目陈列方式

- 使用“唱片架 / 专辑架”的概念。每个项目是一张方形封面，封面下方配一张清楚可读的作品名卡片。
- 首批展示已知项目：`《缚语》`、`《缚育宅姬》`。如果后续增加其他项目，再按同样的组件规则追加。
- 必须优先使用真实项目封面或用户提供的游戏截图，不使用无关的图库图片作为项目封面。
- 封面保持统一的方形比例；项目名称常驻显示，不能只在 hover 时显示，以保证移动端用户也知道每张图对应什么项目。
- 鼠标经过时，封面轻微上移、放大或从架子中抽出；名称卡片同步高亮，并可显示“查看作品 ↗”。动画幅度克制，避免大幅旋转或抖动。
- 点击整张作品卡片打开对应的真实项目页面，使用新标签打开外部链接时需明确设置。链接必须由项目配置提供，不能猜测或伪造。
- 手机端采用每行两张卡片的布局；窄屏下可以改为一张或横向滑动，但名称卡片始终可见，触控后有反馈。
- `《缚语》`、`《缚育宅姬》`的合作介绍仅写已确认的信息。未确认具体分工时，不要写成“独立负责全游戏配乐”等具体职责。

### 5.3 原创音乐展示

- 保留现有音乐文件、曲目名称、曲目列表数据和可试听能力。
- 可将原创曲目以小型封面/音轨卡片方式展示，与合作项目的封面架区分开。
- 点击原创曲目时，优先调用全站共用播放器播放该曲目；不能创建独立的第二个音频播放器。
- 没有封面素材的曲目可以使用网站已有的收音机视觉元素或统一的原创占位封面，不要把它伪装成真实发行专辑封面。
- 可以在作品区提供“回到收音机”或“播放精选”入口，帮助访客继续试听。

## 6. 常驻底部播放栏

底部播放栏参考用户提供的网易云音乐歌曲页交互：<https://music.163.com/#/song?id=3431781214>。参考重点是**固定在窗口底部的播放控制体验和信息层级**，并不代表要把该链接中的歌曲嵌入本网站。底栏实际播放内容仍使用网站已有的音乐文件和歌曲数据。

### 6.1 桌面端布局

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ [小封面] 曲名 / 猫队长     [上一首] [播放/暂停] [下一首]   进度条/时间  音量  列表 │
└──────────────────────────────────────────────────────────────────────────┘
```

**左侧：当前曲目**

- 小型封面或统一的收音机封面。
- 当前曲目名称；有现成作者/系列信息时再显示，缺少信息时不编造。
- 曲目名称过长时省略显示，但可通过可访问文本或提示读取完整名称。

**中部：播放与进度**

- 上一首、播放/暂停、下一首。
- 进度条、当前时间和总时长。
- 进度条可拖动；点击位置和键盘操作需要可用。

**右侧：附加控制**

- 音量控制。
- 播放列表按钮，可打开/收起当前播放列表。
- 视宽度可隐藏非核心的文字标签，但不要隐藏播放/暂停及曲目名称。

### 6.2 固定与交互规则

- `position: fixed` 固定于可视窗口底部，并保持高于正文内容的层级。
- 使用不透明或足够高对比度的底色，不应因背景内容变化而看不清文字和图标。
- 播放栏的控件与收音机同步；它们是同一个全站播放器的不同入口。
- 首次进入网页不自动播放音乐。只有访客主动点击曲目或播放按钮后才开始播放。
- 播放失败时提供可读状态，不要让播放按钮看起来已经正常播放。
- 底栏始终保留足够的点击区域；图标按钮应有文字标签或无障碍名称。
- 页面正文底部设置与播放栏高度匹配的留白，并考虑手机浏览器的安全区域，例如 `env(safe-area-inset-bottom)`。

### 6.3 手机端播放栏

- 仍固定在屏幕底部。
- 第一行显示曲目名称和播放状态；第二行放上一首、播放/暂停、下一首及简洁进度条。
- 音量与播放列表可以折叠到展开面板，但必须保留核心播放控制。
- 不能让底栏遮挡小游戏操作区、作品卡片按钮或页脚链接。

## 7. 页脚与现有元素迁移

以下现有元素不能因重新排版而丢失：

- `make by vvcat` 作者署名。
- 现有访客计数器及其配置（如果仍然正常工作）。
- 现有卡通小猫图像。
- 现有介绍弹窗及关闭按钮 `×`；可调整视觉样式，但保留打开与关闭能力。
- 现有品牌文字与 Logo 图片。

页脚可以加入“回到顶部”入口。合作联系区使用真实配置；未提供联系地址时保留清晰的占位配置项供开发时补齐，不要显示虚假的联系方式。

## 8. 视觉规范

### 8.1 整体风格

关键词：**复古收音机、个人音乐档案、黑橙色猫、像素游戏、温暖、轻微俏皮**。

- 保留现有收音机的外观语言和按钮质感。
- 介绍区采用较干净的排版，避免与收音机争夺视觉焦点。
- 像素小游戏使用像素风字体或等宽字体；普通介绍和作品说明仍以可读性为主。
- 作品展示沿用唱片架/专辑陈列的视觉隐喻，和收音机形成联系。
- 避免过度玻璃拟态、强渐变、霓虹色和高频闪烁动画。

### 8.2 建议色彩

以下为新版的建议色彩，不要求覆盖现有所有颜色；应先检查现有 CSS，再以变量统一调整，尽量减少无必要的重做。

| 用途 | 建议色值 |
|---|---|
| 主文字 / 深色外壳 | `#282522` |
| 暖白底色 | `#F4EEDF` |
| 猫的强调橙 | `#E88736` |
| 次级棕色 | `#A96D3C` |
| 边框 / 木架 | `#CBB99E` |
| 柔和说明文字 | `#736B60` |

### 8.3 动画规范

- 按钮与作品卡片交互采用约 150–250ms 的过渡即可。
- 作品封面悬停时小幅上移/放大，不要触发页面布局跳动。
- 运行游戏时可使用简短的像素动画；长时间自动闪烁和大幅抖动应避免。
- 支持 `prefers-reduced-motion`，减少动态效果时仍可完整使用网站。

## 9. 响应式要求

### 桌面端

- 介绍区左右双栏。
- 收音机尽量保留现有的复古横向布局。
- 合作项目以一排多张方形封面陈列为主。
- 底部播放栏显示封面、曲目、核心播放控制、进度和音量/列表入口。

### 平板端

- 介绍区左右双栏可适当缩小间距；若宽度不足则上下排列。
- 收音机允许缩放，但按钮不能小到难以点击。
- 作品区根据可用宽度调整每行卡片数量。

### 手机端

- 顺序严格保持为：导航 → 介绍文本 → 像素猫小游戏 → 收音机 → 作品展示 → 页脚。
- 导航可折叠，但入口名称明确。
- 收音机内部可以从横向调整为纵向，歌曲列表与功能保持不变。
- 作品卡片名称常驻显示，默认每行两张方形封面。
- 底部播放栏固定显示，并为页面正文增加底部安全留白。
- 触控目标建议不小于约 44 × 44 CSS px；小游戏不能依赖鼠标悬停。

## 10. 开发实现建议

### 10.1 先盘点，再修改

开发前先检查现有项目中的：

- 音频文件、曲目数据及列表加载逻辑。
- 收音机播放/暂停、上一首/下一首、进度、时长和音量控制代码。
- Logo、小猫图片、访客计数器、介绍弹窗与现有 CSS。
- 构建方式和静态部署规则。

尽量复用现有项目结构，不因为增加小游戏或底栏而无故引入大型前端框架或不必要的第三方服务。

### 10.2 播放器状态

建议建立单一的全局播放状态，至少包含：当前曲目索引、播放/暂停状态、播放进度、总时长、音量、播放列表和错误/加载状态。收音机与底部栏都读取并修改同一份状态。

如果现有站点使用原生 `<audio>`，优先保留并扩展现有音频实例；避免每个区域各自创建一个 `<audio>`，否则会出现双重播放、状态不同步或切歌进度丢失。

### 10.3 页面导航

- 给主要区块配置稳定的 ID：`intro`、`radio`、`works`、`about`、`contact`。
- 导航使用锚点滚动；如果头部吸顶，需设置适当的 `scroll-margin-top`，避免标题被头部遮住。
- 点击导航和作品卡片时，不应导致底部播放器组件卸载或音频重新初始化。

### 10.4 小游戏

- 使用原生 JavaScript + Canvas 或轻量 DOM 实现即可，优先考虑加载速度和维护成本。
- 如果使用 Canvas，处理设备像素比，保持像素边缘清晰；若用 CSS 放大像素图，设置合适的 `image-rendering: pixelated`。
- 计时、碰撞与跳跃逻辑应与绘制分开，便于调节难度。
- 游戏键盘事件只在游戏区域启动/聚焦后生效，不要全局占用空格键。
- 游戏应能在没有联网请求的情况下运行，避免第三方服务中断后小游戏无法启动。

### 10.5 性能和可访问性

- 封面和图片按需加载，压缩文件体积；不要让大型图片拖慢第一屏。
- 所有核心操作可以通过键盘和触摸完成。
- 图标按钮提供可读标签；焦点状态清晰。
- 图片提供必要的替代文本；装饰图片可使用空替代文本。
- 颜色对比度保证正文及播放状态可读。
